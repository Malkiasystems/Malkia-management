CHANGE 1 — ImportOrder.tsx (Add Shipment double-post):
  0. Shipment numbering now uses MAX(shipment_number)+1 fetched fresh
     from the DB instead of row count+1. Count-based numbering would
     reissue #3 on IMP-10-0004 after the cleanup deleted rows #2 and #4.
  1. shipSaving in-flight guard: early return + button disabled with
     'Creating...' label while the flow posts. Fix for the triple-click
     that created shipments #2/#3/#4 and the duplicate TZS 741,150
     freight payment.
  2. On failure, order detail reloads before the modal lets you retry,
     so remaining-to-ship validation runs against real DB state.
  3. After a freight-paid-now payment, import_orders.total_freight_tzs
     is recomputed from import_payments. Previously this path never
     updated the stored column, so ImportRegister understated freight.

CHANGE 1b — ImportOrder.tsx (journal ref collision, added 31 Aug):
  Shipment-flow freight journals now use ref JV-{order}-FS{n} instead
  of JV-{order}-F{n}. journals.ref has a UNIQUE index and recordPayment
  numbers ITS freight journals F{payment count}, so the two schemes can
  collide. That exact collision (F2) is what killed the first Create
  Shipment click on 27 Aug and stranded half-created shipment #2.

CHANGE 3 — HRMPayroll.tsx (added 31 Aug):
  The payroll voucher insert now surfaces errors instead of swallowing
  them. It failed silently on every run to date because the vouchers
  type constraint had no 'payroll' type (fixed by migration 037).
  The 2026-08 run was re-posted directly in the DB on 31 Aug with
  corrected figures (PAYE 73,750 Barbra only, SDL 0, net 6,945,250)
  and its voucher now exists. April/May runs still have no vouchers.

CHANGE 2 — SalesDayBook.tsx + salesDayBookExport.ts (expenses):
  1. Day Book expenses filter by PAYMENT METHOD, not voucher type:
     petty_cash, plus cash_payment paid by physical cash. Electronic
     methods (rtgs, mpesa, mixx) and null methods are excluded for
     every viewer. Reason: the bank-payment page is a legacy alias of
     the cash payment screen and no bank_payment type vouchers exist
     (verified in prod), so a type filter excluded nothing. Salaries,
     supplier transfers, and other back-office spends are electronic,
     so this keeps them off cashiers' screens. Cashiers keep full
     visibility of drawer expenses they record.
  2. Caveat: a shop expense paid via M-Pesa will also be hidden from
     the Day Book. Erring toward hiding, per Joe's sensitivity call.
     A sensitive spend paid in PHYSICAL cash will still show.
  3. Summary PDF: expense section retitled 'Cash & Petty Expenses'
     since it no longer claims to be total expenses. The export lib
     also gained an optional expensesHidden flag that prints
     'Restricted' instead of figures; currently nothing passes it, it
     is inert and ready if role-gating is ever wanted back.

CHANGE 4 — P&L / Budgets / Banks (added 1 Sep):
  1. P&L period actuals, Budget vs Actual actual spend, and the Banks
     month in/out card all read raw journal_lines for a date range in
     one unpaginated call. PostgREST caps that at 1,000 rows; August
     2026 needs 1,231, so 231 lines were silently dropped. On screen:
     6010 salaries showed 230,000 (true 7,396,000), 4010 B2C sales
     showed 33,333,000 (true 42,210,000). All three now call the
     account_period_totals() function from migration 038, which
     aggregates server-side and returns one row per account.
  2. P&L gained an Export PDF button (actuals tab), same chrome as the
     Trial Balance / Balance Sheet PDFs, same figures and row filter as
     the screen for whichever period is selected.
  3. Still capped, NOT fixed here: the per-account ledger drilldown in
     Chart of Accounts (and the Banks ledger view) list raw lines and
     will truncate on busy accounts. They need pagination like
     useInterimRecon already does. Later session.

What changed (all inside addShipment + one button):
  0. Shipment numbering now uses MAX(shipment_number)+1 fetched fresh
     from the DB instead of row count+1. Count-based numbering would
     reissue #3 on IMP-10-0004 after the cleanup deleted rows #2 and #4.
  1. shipSaving in-flight guard: early return + button disabled with
     'Creating...' label while the flow posts. This is the fix for the
     triple-click that created shipments #2/#3/#4 and the duplicate
     TZS 741,150 freight payment on IMP-10-0004 (27 Aug 2026).
  2. On failure, order detail reloads before the modal lets you retry,
     so remaining-to-ship validation runs against real DB state instead
     of the stale pre-click snapshot.
  3. After a freight-paid-now payment, import_orders.total_freight_tzs
     is recomputed from import_payments (same figure recordPayment
     maintains). Previously this path never updated the stored column,
     so ImportRegister understated freight for shipment-declared
     payments. total_landed_tzs is not touched; doReceiveShipment owns it.

Deploy AFTER running the data cleanup for IMP-10-0004 (see chat), so the
cleanup happens on known data and the fix prevents recurrence.
